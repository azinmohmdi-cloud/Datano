# Backlog جامع دیتانو با استراتژی Frontend-First

## خلاصه و مبنای سند

تاریخ ثبت: ۲۰۲۶-۱۰-۱۱. این فایل مرجع مرکزی انتخاب، وابستگی، معیار پذیرش و وضعیت تسک‌هاست. شناسه‌ها پایدارند و در بازبینی‌های آینده نباید دوباره شماره‌گذاری شوند.

**ترتیب مصوب:** ابتدا همه صفحات و حالت‌های UI آماده شوند؛ سپس اتصال واقعی جریان‌ها به بک‌اند انجام شود. دادهٔ نمونه فقط در محیط طراحی و تست مجاز است.

بررسی شامل سه فایل `AGENTS.md`، مستندات محصول و UX، cookbook فرانت‌اند، کدهای موجود، تست‌ها، تنظیمات، اسکریپت‌ها و وابستگی‌های مستقیم بوده است. مبنای وضعیت فعلی:

| بخش | وضعیت مشاهده‌شده |
|---|---|
| Frontend | Next.js، اجزای Button/Table، Query Provider، صفحات نمونه فاکتور و مسیرهای محلی mock؛ صفحات محصول وجود ندارند. |
| زبان و نمایش | سند HTML انگلیسی است؛ فونت‌های فعلی لاتین‌اند. تنظیم `rtl` در shadcn به‌تنهایی RTL محصول را فراهم نکرده است. |
| ارتباط API | Orval تنظیم شده، ولی کلاینت تولیدشده موجود نیست؛ نام متغیر محیطی API در نمونه و کد ناسازگار است. |
| Backend | APIهای auth/user/role با JWT، refresh cookie، ذخیره‌سازی در حافظه و کاتالوگ JSON وجود دارند. |
| دامنه محصول | سایت، اثبات مالکیت، اتصال گوگل، تحلیل و پیشنهاددهی پیاده‌سازی نشده‌اند. |
| آزمون | Pytest موجود است؛ fixtureهای مشترک و سه نام متد تکراری محدودیت دارند. ابزار تست فرانت‌اند تنظیم نشده است. |
| محیط محلی | در بررسی مبنا، `node_modules` و محیط مجازی بک‌اند موجود نبودند؛ Node مشاهده‌شده `22.17.0` از حداقل موردنیاز Orval پایین‌تر بود؛ PDM در PATH یافت نشد. |
| Git | مخزن فعلی یک monorepo در ریشه Datano است؛ برخی متن‌های قدیمی هنوز مخزن‌های مستقل را توصیف می‌کنند. |

مرجع نیازمندی‌ها، تصمیم‌های قطعی MVP و UX نهایی است. وضعیت کد از نیازمندی آینده تفکیک می‌شود. تست اجرایی، build، اجرای سرویس یا تولید OpenAPI در بررسی مبنا انجام نشده؛ تحلیل ایستای فایل‌های Python موفق بوده است. وضعیت محیط و کد پیش از اجرای هر تسک دوباره بررسی شود.

## قواعد پذیرش و کنترل کیفیت Backlog

- هر تسک یک خروجی مستقل دارد. وابستگی‌ها پیش از شروع تسک باید تکمیل و راستی‌آزمایی شده باشند؛ انتخاب تسک، اجرای خودکار پیش‌نیازهایش را مجاز نمی‌کند.
- تسک UI با fixture خصوصی پذیرفته می‌شود؛ تسک integration فقط با قرارداد واقعی و رفتار واقعی پذیرفته می‌شود. تکمیل UI به معنی تکمیل قابلیت محصول نیست.
- برای تغییر رفتار بک‌اند، Red → Green → Refactor، آزمون‌های مرتبط و suite کامل الزامی است. تغییر persistence به آزمون PostgreSQL و migration نیاز دارد.
- برای فرانت‌اند، lint، TypeScript، آزمون رفتاری مرتبط و بررسی فارسی/RTL لازم است؛ تغییر route، dependency یا rendering نیازمند build است.
- تغییر API باید OpenAPI واقعی، تولید Orval و مصرف‌کننده را هماهنگ کند. Backlog endpoint یا schema فرضی تعریف نمی‌کند.
- معیارهای مشترک شامل عدم افشای secret، جداسازی کاربران و منابع، تفکیک دادهٔ ناموجود از صفر و نمایش قابل‌اقدام خطا است.
- checkbox فقط پس از تحقق معیارها و موفقیت بررسی‌های لازم تغییر می‌کند؛ Epic تنها پس از تکمیل تمام تسک‌های لازم کامل می‌شود.
- اعتبارسنجی فایل Backlog شامل یکتایی شناسه‌ها، صحت لینک منابع، وجود همهٔ وابستگی‌ها، نبود چرخه و تقدم پیش‌نیازها بر مصرف‌کننده است. بازهٔ وابستگی `FE-006` تا `FE-027` شامل تک‌تک ۲۲ تسک این بازه است.

## تصمیم‌ها و محدودیت‌های ثبت سند

- مسیرهای صفحات عمومی `/`، `/services` و `/about`؛ صفحات هویت `/login`، `/signup` و `/forgot-password`؛ پروفایل `/profile`؛ فضای سایت زیر `/websites/[websiteId]` و پنل مدیر `/admin/users` در نظر گرفته شوند. مراحل بازیابی در همان جریان بازیابی باشند؛ جزئیات مدیر می‌توانند در نمای فقط‌خواندنی همان پنل نمایش داده شوند.
- Search Console نخستین منبع عملیاتی است تا مسیر کامل گزارش و اولین قاعده زودتر قابل‌آزمون شود؛ GA4 و Ads همچنان الزامات MVP هستند.
- PostgreSQL هنگام هویت پایدار اضافه می‌شود؛ Celery/Redis هنگام دریافت داده. cache عمومی، موتور ABAC عمومی و schema کامل همهٔ حوزه‌ها پیش‌نیاز ساخت صفحات نیستند.
- پرداخت، اشتراک، Excel، JetSEO، دعوت و انتقال سایت، مدیریت قواعد، عملیات تغییر کاربران در پنل، بلاگ، FAQ، دموی عمومی تعاملی و یادگیری ماشین خارج از این Backlog هستند.
- اطلاعات SMTP و گوگل از تنظیمات خصوصی تأمین می‌شوند؛ نبود دسترسی واقعی، مانع تکمیل تسک مربوط است و با mock پوشانده نمی‌شود.
- دامنهٔ ثبت این سند فقط ایجاد `docs/backlog.md` است؛ کد، تنظیمات و فایل‌های `AGENTS.md` تغییر نمی‌کنند و commit خودکار انجام نمی‌شود.
- این سند شامل ۱۵ Epic و ۱۰۲ تسک است: ۲۸ تسک `P0`، ۷۱ تسک `P1` و ۳ تسک `P2`. در زمان ثبت، هیچ تسک محصولی اجرا یا تکمیل نشده است؛ اجرای هر تسک به درخواست صریح بعدی نیاز دارد.
